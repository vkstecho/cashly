## Catalog behavior

- The first `channels.list` request uses one `id` filter with `snippet,contentDetails`. The configured public `YOUTUBE_CHANNEL_ID` takes precedence. Otherwise the candidate from the prior site is `UCfhIm-gZXMWel81oPMSm2qQ`. Before the first publish, the API must match the ID and official title, return the uploads playlist and confirm the official handle. If `snippet.customUrl` does not provide a usable handle, an independent `forHandle` request must return that same ID. Subsequent runs use the verified ID. The key uses Google's supported `key` parameter, with credential-bearing URLs kept out of output. [YouTube channels.list](https://developers.google.com/youtube/v3/docs/channels/list)
- The hourly job follows every uploads and public playlist page, collects the memberships in API order, deduplicates video IDs and requests metadata in batches of 50. A missing ID gets one separate successful recheck before removal. Private, nonpublic, unavailable and foreign videos are excluded. Broken pagination, API failure, corrupt metadata and unexpected empty results leave the prior tracked catalog intact. An intentional empty publish requires the owner to enable the explicit `allow_empty` input.
- Live and upcoming discovery uses supported `search.list` for the verified channel, one query each for `live` and `upcoming`, with bounded pagination. The authoritative item state and times come from `videos.list`. A verified scheduled or live item can have unknown or zero duration. Completed streams with an actual end time are labelled Recorded. Website and Learn show the viewer's local scheduled time. Live labels show when checked and become unconfirmed when the published API verification is over two hours old or the expected start has passed. The clients never poll the Data API or imply minute-level status. [YouTube search.list](https://developers.google.com/youtube/v3/docs/search/list) · [YouTube videos.list](https://developers.google.com/youtube/v3/docs/videos/list)
- Complete reconciliation runs at minute 17 UTC each hour, or **minute 47 in India**. A typical run needs two search calls. The per-run limits are four search calls and 300 other API calls including retries. Before manual reruns, check usage in the actual Google Cloud project. Google's published default is 100 search calls per day and 10,000 units combined for the other endpoints. The guard stops the candidate if full reconciliation would exceed its budget. Transient rate limits, timeouts and HTTP 5xx retry with bounded backoff. Permanent criteria and key errors stop immediately. [YouTube quota calculator](https://developers.google.com/youtube/v3/determine_quota_cost)
- Schema version 1 is additive. Playlist groups reference stable video IDs. Both clients validate the same HTTPS JSON, use the same cache format and discard invalid or expired cached data when encountered. A populated record expires in clients at 30 days. Unchanged metadata creates no routine commit. A verified timestamp is renewed after 23 days, and a publishing job checks exact deployed bytes. The JSON field `lastSuccessfulPublication` records a prior catalog observation only when its live bytes were verified before generating the next catalog. The exact new publication time is reported separately after the live endpoint passes. If API failure lasts through the retention period, both new clients stop using the stale catalog. The static hosting endpoint still serves its last Git artifact until an approved deployment replaces it.
- Configure `YOUTUBE_SHORTS_PLAYLIST_ID` only if it identifies a public playlist on the verified channel. Creator overrides in `content/video-overrides.json` can pin `contentType`, `language`, `tags` and `tools` by stable video ID. Shorts require creator evidence. Unknown classification remains discoverable. Hindi and English include creator-confirmed mixed or Hinglish records. The official player and Open in YouTube fallback remain available. Existing V8.1 APKs can read the refreshed v1 list from HTTPS. Their bundled UI needs the updated app code to display newly added playlist and broadcast controls.

## One production approval and activation checklist

1. Apply and review the ZIP against the current official checkout. With approval, commit the overlay to `main` in one change. Existing ordinary Git-to-Vercel deployment remains independent of YouTube. Keep the previous source SHA and Vercel deployment for rollback.
2. From the **new main commit**, start a **new** **Sync Cashly YouTube catalog** workflow. The existing `YOUTUBE_API_KEY` Secret is reused. Keep confirmed `CASHLY_CATALOG_REPOSITORY=vkstecho/cashly`, `CASHLY_CATALOG_BRANCH=main` and `CASHLY_VERCEL_DEPLOY_MODE=git`. To check identity only, use `resolve_channel=true`. For a full non-publishing run leave `resolve_channel=false` and `publish=false`. For the approved production publication, ensure `CASHLY_CATALOG_PUBLISH=true` and run with `publish=true`, `resolve_channel=false` and `allow_empty=false`. The full run verifies identity before making any catalog commit.
3. Use the run summary to check the authenticated channel, uploads ID, reconciliation counts and catalog validation. A successful changed run records the exact Git commit and separately verifies that the Vercel custom domain returned matching JSON with revalidation and native WebView CORS. Match the SHA to the Vercel project deployment. If bot-commit deployment fails, confirm Vercel's Git status before choosing the included `hook` mode. Only then create a main-branch Deploy Hook in the authorized Vercel project and store its URL as the GitHub Actions Secret `VERCEL_DEPLOY_HOOK_URL`. An already pushed revision can be redeployed through Vercel once to close that gap. Avoid simultaneous Git and hook deployment for the same commit. [Vercel Git integration](https://vercel.com/docs/git/vercel-for-github) · [Deploy Hooks](https://vercel.com/docs/deploy-hooks)
4. Confirm the live website and Learn show actual content, playlists and states present on the channel. Check one embeddable item, external fallback, language and Shorts where creator-confirmed, and native WebView refresh on Android. Observe one automatic scheduled run. A manual successful run proves integration, while a scheduled run proves hourly activation.

If API verification fails, use the **single safe reason** in the Cashly YouTube check annotation. `SERVICE_DISABLED` means enable YouTube Data API v3 in the API key's project. `API_KEY_INVALID` means validate or replace that key in the existing repository Secret. `API_KEY_SERVICE_BLOCKED` means allow YouTube Data API v3 for that key. A referrer or IP restriction code means use a key restricted to YouTube Data API v3 whose application restriction is compatible with the approved Actions runner. A quota code means inspect that project's quota and wait for reset or authorize a revised schedule. A channel identity or playlist error identifies the corresponding public repository variable. Do not change key or cloud configuration based solely on an HTTP status. [Official YouTube API errors](https://developers.google.com/youtube/v3/docs/errors)

For rollback, pause catalog publication, select the previous compatible Vercel deployment and reconcile `main` to the last verified catalog before restoring the schedule. Preserve bookmarks and application data. The YouTube overlay requires no Firebase, DNS, financial, SMS, signing or Capacitor changes.
